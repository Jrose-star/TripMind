# 阶段二：架构设计

> 状态：已确认 · 日期：2026-11-10

## 1. 整体架构

分层：前端 → API 网关 → Agent 编排层 → 工具层 → 数据/外部服务层。

```
┌─────────────────────────────────────────────────────────┐
│                    前端 (Web UI)                         │
│        需求输入 → 流式展示攻略 → 历史会话                │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP / SSE (流式)
┌──────────────────────▼──────────────────────────────────┐
│              FastAPI 服务层 (API 网关)                   │
│   REST 接口 + SSE 流式 + 会话管理 + 参数校验             │
└──────────────────────┬──────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────┐
│              LangGraph 多智能体编排层                     │
│  意图解析 → POI检索 → 行程编排 → 预算校验 → 攻略写作      │
│   (checkpointer 持久化 + 多轮追问 + 工具调用)            │
└──────────┬────────────────────────┬─────────────────────┘
           │                        │
┌──────────▼──────────┐   ┌─────────▼──────────────────┐
│   MCP 工具层         │   │   数据层                    │
│ 高德地图 / 天气      │   │ PostgreSQL (会话/行程/历史) │
│ (先空壳，后接真实)   │   │ Redis (缓存/限流)          │
└─────────────────────┘   │ pgvector (语义检索)        │
                          └────────────────────────────┘
           │                        │
           └──────────┬─────────────┘
                      │
        ┌─────────────▼─────────────┐
        │  可观测 (LangSmith/Langfuse)│
        └───────────────────────────┘
```

## 2. 核心 Agent 流程（LangGraph 状态机）

5 个核心节点 + 条件路由：

| 节点 | 职责 | 输入 → 输出 |
|------|------|------------|
| `intent_parse` | 意图解析 | 原始输入 → 结构化需求 |
| `clarify` | 多轮追问 | 信息不足时反问，补全后回到 intent_parse |
| `poi_search` | POI 检索 | 结构化需求 → 候选 POI 列表（经 MCP） |
| `itinerary_plan` | 行程编排 | POI + 约束 → 分天分时段行程 |
| `budget_check` | 预算校验 | 行程 → 分项预算 + 告警 |
| `guide_write` | 攻略写作 | 行程 + 预算 → Markdown/JSON 攻略 |

**状态流转**：

```
START → intent_parse ─┬─ 信息充足 → poi_search → itinerary_plan
                      │                                │
                      └─ 信息不足 → clarify ───────────┘
                                                     │
                              ┌──────────────────────┘
                              ▼
                        budget_check ─┬─ 超预算 → 调整行程(回 itinerary_plan)
                                      │
                                      └─ 达标 → guide_write → END
```

**关键设计点**：
- `checkpointer` 把节点状态存到 PostgreSQL，支持断点续跑
- 预算超支回环到行程编排，设最大重排次数防死循环
- 每个节点对外部 API 有超时 + 重试 + 降级

## 4. 数据流时序

```
用户 → 前端
  │  ① 提交需求文本
  ▼
FastAPI ── ② 创建会话 → 调用 LangGraph(thread_id)
  │
  ▼
intent_parse ──③ 信息不足 → clarify → 追问用户(SSE)
  │
  ▼
poi_search ──④ 调 MCP(空壳/真实) → 候选 POI
  │
  ▼
itinerary_plan ──⑤ 编排 → 分天行程
  │
  ▼
budget_check ──⑥ 校验 → 超支则回环重排
  │
  ▼
guide_write ──⑦ 生成攻略 → 存 PG
  │
  ▼
FastAPI ──⑧ SSE 流式回推 → 前端渲染
```

**数据落地**：会话/行程/攻略存 PostgreSQL；POI/天气缓存到 Redis；历史行程向量化存 pgvector（Could-have）。

## 5. 关键接口设计（草案）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/plan` | POST | 发起规划，返回会话/线程 ID |
| `/api/plan/{id}/stream` | GET(SSE) | 流式返回节点进展与最终攻略 |
| `/api/plan/{id}` | GET | 查询某次规划完整结果 |
| `/api/history` | GET | 历史会话列表 |
| `/api/health` | GET | 健康检查 |

## 6. 结论

- 核心是 LangGraph 编排的 5 节点状态机，含多轮追问 + 预算回环
- MCP 先空壳、Docker 后置，均预留接口位，不影响主链路
- 全栈：FastAPI + Web UI，SSE 流式联动
