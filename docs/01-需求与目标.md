# 阶段一：需求与目标

> 状态：已确认 · 日期：2026-11-10

## 1. 项目目标

**简历定位**：一个能独立完成「需求理解 → POI 检索 → 行程编排 → 预算校验 → 攻略写作」全链路的多智能体旅行规划 Agent。

体现的能力闭环：LLM 应用工程（LangGraph 编排）+ 工具集成（MCP）+ 服务化（FastAPI）+ 可观测（LangSmith/Langfuse）。

**核心能力**：
- 自然语言意图解析（提取目的地、天数、预算、偏好、人数）
- 多源 POI 检索与真实数据落地（高德地图 + 天气 API）
- 约束驱动的行程编排（时间 / 地理 / 预算三重约束）
- 可解释的预算校验与偏差告警
- 结构化 + 自然语言双形态的攻略输出

**边界（明确不做）**：
- 不做实时酒店 / 机票 / 门票的真实下单与支付
- 不做多用户协作、账号体系与社交功能
- 不做客服式闲聊，超出旅行规划范围一律明确拒绝或转引导

## 2. 需求澄清结论

| # | 问题 | 结论 |
|---|------|------|

## 4. 功能范围（MoSCoW）

**Must-have**
- 自然语言意图解析（目的地/天数/预算/偏好/人数）
- 高德 POI 检索 + 天气查询（经 MCP）
- 行程编排（按天、按时段、地理聚类）
- 预算校验（分项汇总 + 超支/结余告警）
- 攻略输出（Markdown + JSON 双形态）

**Should-have**
- 简单 Web 前端（输入需求 → 查看攻略）
- 流式输出（SSE，边生成边显示）
- 多轮追问补全（信息不足时反向提问）

**Could-have（暂缓，MVP 完成后优化）**
- 历史行程记忆 / 用户偏好沉淀
- 图文攻略（配 POI 缩略图）
- 行程可编辑、可重排

**Won't-have（本期不做）**
- 真实下单 / 支付 / 预订
- 多人协作、账号体系
- 客服闲聊与旅行外话题

## 5. 非功能约束

| 维度 | 目标 |
|------|------|
| 延迟 | 单次完整规划 P95 ≤ 20s；首 token 流式 ≤ 2s |
| 成本 | 单次 token 预算可控；缓存 POI/天气，避免重复调用 |
| 可观测 | LangSmith/Langfuse 全链路 trace；关键节点打点；结构化日志 |
| 可扩展 | 状态持久化到 PostgreSQL（checkpointer），支持断点续跑与并发会话隔离 |
| 隐私/密钥 | API Key 走环境变量，禁止硬编码入库；行程数据不落第三方日志 |
| 容错 | 外部 API 超时/限流自动重试 + 降级 |

## 6. 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| Agent 编排 | LangGraph | 多智能体、状态机、checkpointer、人工介入 |
| 服务层 | FastAPI | 异步高性能、自动 OpenAPI、适配 SSE |
| 关系存储 | PostgreSQL | 存会话/行程/历史，JSONB 够用 |
| 缓存/队列 | Redis | 缓存、限流、分布式锁 |
| 向量检索 | pgvector（首选）/ Milvus（备选） | 语义召回，部署成本低，与 PG 同库 |
| 地图 POI | 高德地图 API | 国内覆盖全、文档友好、免费额度够演示 |
| 天气 | 天气 API（和风/心知，备选 Open-Meteo） | 行程时间敏感，需预报辅助 |
| 工具协议 | MCP | 标准化工具接入，核心卖点 |
| 可观测 | LangSmith / Langfuse | 全链路 trace + 成本统计；Langfuse 可自托管 |
| 模型 | 多模型可插拔 | 主用 DeepSeek/Qwen 降本，复杂推理切强模型 |

## 7. 风险清单

| # | 风险 | 缓解 |
|---|------|------|
| R1 | 高德/天气 API 限流或额度超限 | Redis 限流 + 缓存 + 重试退避 + 降级 |
| R2 | LLM 幻觉（编造 POI/价格） | POI 强制绑定真实数据源；输出前校验 ID |
| R3 | 路线不可达 / 地理不合理 | 地理聚类 + 路径距离校验 + 通勤时间预算 |
| R4 | 预算估算不准 | 区间估算 + 标注"预估" + 误差范围 |
| R5 | MCP 接入复杂、版本不稳 | 先 1 个 MCP Server 打通 MVP，再扩展 |
| R6 | 模型不稳定 | 多模型可插拔 + 熔断降级 + 重试 |
| R7 | 长链路 token 成本失控 | 短链编排、结构化中间态、结果缓存 |
| R8 | 会话状态丢失 / 并发冲突 | checkpointer 持久化到 PG，会话隔离 |
| R9 | 隐私泄露 | 数据脱敏、密钥不落库、日志裁剪 |
| R10 | 需求膨胀范围蔓延 | MoSCoW 冻结 + 阶段化验收 |

## 8. 验收标准

**MVP 定义**：用户输入一句旅行需求 → Agent 完成意图解析、POI 检索、行程编排、预算校验 → 输出结构化 + 可读攻略，全程可在 Web 界面或 API 完成。

| 指标 | 目标 |
|------|------|
| 意图解析字段准确率 | ≥ 90%（50 条样本） |
| POI 信息真实性 | 100%（无幻觉 POI） |
| 单次完整规划成功率 | ≥ 95% |
| 端到端 P95 延迟 | ≤ 20s |
| 预算校验偏差 | 分项误差 ≤ ±30%，明确标注 |
| 降级可用性 | 天气不可用时 100% 降级出攻略 |
| 可观测覆盖 | 核心链路 100% trace |
